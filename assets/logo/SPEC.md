> 用途：在 Figma / Illustrator / 代码中按本规范重建标志，产出 SVG 与多尺寸 PNG。
> 数据来源：对1024×1024 基准画布逐像素量取 + 矢量解算，非目测估算。
>
> **当前状态**：矢量定稿已完成，`omninotation-logo-v1.svg` 为唯一权威源文件。
> 下方「实测色偏」一节保留为历史记录 —— 那是位图初版的问题，已在矢量重建中修正。

### 深色底为什么必须换色

松绿 `#064E3B` 在近黑底（`#0C1A16`）上的对比度极低，**收笔圆点会糊进背景、识别点彻底丢失**。深色版把圆点与字标一起换成 `#E8F5F1`，环与内横条保持青绿不变。

### 为什么要小尺寸补偿版

主版几何在 32px 下环线仅约 2.1px、双条约 2.4px、条间仅约 1.0px，抗锯齿后**两条糊成一条灰带**，「圈注文字」语义消失，只剩一个 "C"。

1024 基准 → 32px 换算：1 基准px ≈ 0.040 输出px。要让特征在 32px 下可分辨，基准尺寸下限为：

| 特征 | 需要的输出尺寸 | 基准下限 | 补偿版取值 |
|---|---|---|---|
| 环线 | ≥ 2.8px | ≥ 70 | **72** |
| 条高 | ≥ 3.0px | ≥ 75 | **78** |
| 条间距 | ≥ 1.6px | ≥ 40 | **40** |

补偿版同时把圆点放大到⌀92 并收窄条宽以适配加粗后的内腔。

实测 32px 逐行不透明度剖面（中心列）：上壁 3px / 条1 4px / 缝 2px / 条2 4px / 下壁 4px —— 两条清晰可分辨。

**48px 及以上必须回到主版**，补偿版的加粗会让大尺寸下显得笨重。

## 五、最小尺寸可读性

**已实测验证**：主版几何在 32px 下两条糊成灰带，**不可用**。因此提供独立的小尺寸补偿版（见「三、为什么要小尺寸补偿版」）。

| 尺寸 | 应使用 | 验证结果 |
|---|---|---|
| 48px 及以上 | 主版 | ✅ 环 / 双条 / 圆点全部清晰 |
| 32px | 补偿版 | ✅ 剖面 3/4/2/4/4px，两条可分辨 |
| 16px | 补偿版 | ⚠️ 语义仍可读，但细节已损失；favicon 场景可接受 |

**不要**为省事在 16px 下换成单一实心色块，会丢掉全部识别特征。

## 六、渲染管线

所有 PNG 都从 SVG 经无头渲染降采样得到，**不从位图放大、不手工重绘**。这是保证色值与几何零偏差的唯一可靠路径。

```
SVG（唯一事实来源）
  → Edge headless 渲染
  → 裁透明边 + 固定视觉留白（主版 6.25%，补偿版 7.8%）
  → Pillow LANCZOS 降采样
  → 逐像素校验主色数量
```

| 脚本 | 作用 |
|---|---|
| `_tools/outline_wordmark.py` | 字标转曲（fontTools → path） |
| `_tools/build_full_logo.py <light\|dark>` | 组装完整标识 SVG |
| `_tools/build_mark_dark.py` | 生成深色底 mark SVG |
| `_tools/render_assets.py [all\|full\|mark]` | 渲染 + 导出 + 逐像素校验 |
| `_tools/build_store_main.py` | 440×280 商店主图 |

前置：Edge（`C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`）、Pillow、fontTools。

### 四个已踩过的坑

1. **Edge 截图是异步的** —— 进程返回 rc=0 时文件还没写完，必须轮询等待，否则误判失败。
2. **Edge 无法写入 E: 盘** —— 必须先把 SVG 拷到系统临时目录再渲染。
3. **嵌套 TransformPen 会覆盖平移** —— 字标转曲时若用两层 `TransformPen`，内层的逐字平移会被外层缩放覆盖，12 个字全部叠在原位。正确做法是**单一仿射变换**：`x' = LEFT + (penX + glyphX) * sx`。
4. **抽取 SVG 片段必须连 `<defs>` 一起搬** —— 片段里残留 `mask="url(#…)"` 而页面上没有该定义时，浏览器会静默丢弃整个元素；把引用删掉又能显示，但断口一类的遮罩效果就没了。所以要么整段丢弃引用（并接受图形变化），要么内联 `<defs>`，商店主图取后者。

## 七、遗留问题

1. **商店主图**（已修，2026-10-06）：早期版本抽取 SVG 片段时把 `mask` 引用与元素自带
   `fill` 一并清掉，导致**断口被填平、内横条成空心**。现在 `_tools/build_store_main.py`
   会把源 SVG 的 `<defs>` 内联进片段所在的 `<svg>`，并保留各元素自己的 fill/stroke

   条 1 / 条 2 中心行最长连续青绿 16 px → 101 / 99 px。
